# gisila_doc

> The OpenAPI-aware variant of the [gisila](../gisila) MVC framework.
> Generate **OpenAPI 3.1** specs **and** the gisila runtime route
> registration from one annotated Dart controller.

```dart
@Controller('/users', ['Users'])
class UsersController {
  @Get('/{id}', summary: 'Fetch a user')
  Future<User> getUser(String id, UserService users) => users.find(id);

  @Post(
    '/',
    summary: 'Create a user',
    config: RouteConfig(rateLimit: RateLimitConfig(requestsPerMinute: 60)),
  )
  Future<User> createUser(CreateUserForm form, UserService users) =>
      users.create(name: form.name.value!, email: form.email.value!);
}
```

```dart
final spec = OpenApiSpec(info: ApiInfo(title: 'Demo', version: '1.0.0'));
final app = GisilaApp(config: AppConfig(...));
final router = Router();

app.registerService<UserService>(UserService.new);
UsersController().attachToApp(app, router, spec);
router.mount('/', docsHandler(spec));   // /openapi.json · /docs · /redoc

app.registerController(attacher: (app, mainRouter, {String prefix = ''}) {
  mainRouter.mount('/', router.call);
});
await app.start(host: '0.0.0.0', port: 8080);
```

Path parameters, typed form schemas, response schemas, status codes,
per-route rate limit / timeout / permission middleware, **and** Swagger
UI are all derived automatically. Routes run through the same MVC
pipeline as gisila core (error mapping, DB session, AuthN/AuthZ, …).

> **Migrating from 0.1.x?** The generated extension was renamed from
> `attachOpenApi(spec, router)` to
> `attachToApp(app, router, spec, {prefix})`, and gisila_doc now
> re-exports the gisila runtime. See [CHANGELOG.md](CHANGELOG.md).

---

## What's in the box

* `@Controller` / `@Get` / `@Post` / `@Put` / `@Patch` / `@Delete` /
  `@Head` / `@Options` routing annotations.
* `@Path` / `@Query` / `@Header` / `@Body` parameter annotations —
  **usually not needed** because the generator infers location from name and type.
* `@Returns` / `@ApiResponse` / `@Tag` for fine-grained metadata.
* `@QueryDoc` / `@BodyDoc` for documenting raw-`Request` handlers.
* Build-time JSON Schema generation from Dart classes.
* A runtime `OpenApiSpec` you can extend programmatically.
* A bundled `docsHandler` that serves the spec, Swagger UI, and ReDoc.

## Authoring a controller

```dart
import 'package:gisila_doc/gisila_doc.dart';
import 'package:shelf/shelf.dart';
import 'package:shelf_router/shelf_router.dart';

import '../models/user.dart';

part 'users_controller.g.dart';   // generated by build_runner

@Controller('/users', ['Users'])
class UsersController {
  /// Returns every user, optionally paginated.
  @Get('/', summary: 'List users')
  Future<List<User>> listUsers({int? limit, int? offset}) async => ...;

  @Get('/{id}', summary: 'Fetch a user', operationId: 'getUserById')
  @ApiResponse(404, description: 'User not found')
  Future<Response> getUser(String id) async => ...;

  @Post('/', summary: 'Create a user')
  Future<User> createUser(CreateUser body) async => ...;

  @Delete('/{id}', summary: 'Delete a user')
  Future<void> deleteUser(String id) async => ...;
}
```

Run `build_runner` once (or keep it running in watch mode):

```bash
dart run build_runner build --delete-conflicting-outputs
# or:
dart run build_runner watch
```

This creates `users_controller.g.dart` with an extension method
`attachToApp(GisilaApp app, Router router, OpenApiSpec spec,
{String prefix = ''})` that registers the routes via
`gisilaRoute(...)` and contributes the matching operations / schemas
/ tags to the spec.

## Mounting docs

```dart
import 'package:shelf/shelf_io.dart' as io;
import 'package:shelf_router/shelf_router.dart';
import 'package:gisila_doc/gisila_doc.dart';

import 'controllers/users_controller.dart';

Future<void> main() async {
  final spec = OpenApiSpec(
    info: ApiInfo(
      title: 'My API',
      version: '1.0.0',
      description: 'Full description here.',
    ),
    servers: [ApiServer(url: 'http://localhost:8080')],
  );

  final app = GisilaApp(config: AppConfig());
  app.registerController(attacher: (app, router, {prefix = ''}) {
    UsersController().attachToApp(app, router, spec, prefix: prefix);
    // Serves /docs (Swagger UI), /redoc and /openapi.json. Mounted after
    // the controllers, so their routes take precedence.
    router.mount('/', docsHandler(spec));
  });

  await app.start(port: 8080);
  print('Docs at http://localhost:8080/docs');
}
```

## Annotation reference

### `@Controller(path, tags)`

Marks a class as a controller.

| Argument | Default | Description |
| -------- | ------- | ----------- |
| `path` | `''` | URL prefix prepended to every route in the class. |
| `tags` | `[]` | Default OpenAPI tag(s) applied to all operations. |

### HTTP-verb annotations

All share the same optional fields:

```dart
@Get('/path',
  summary: 'Short description',
  description: 'Long markdown description',
  operationId: 'uniqueId',   // defaults to methodName
  deprecated: false,
  tags: ['extra-tag'],
  statusCode: 200,           // success status; Post defaults to 201
)
```

### Parameter annotations

| Annotation | Source | Notes |
| ---------- | ------ | ----- |
| `@Body({contentType, required})` | Request body | Usually inferred; use to mark optional or change content type. |
| `@Query({name, description, example})` | Query string | Inferred for primitive types. |
| `@Path({name, description, example})` | URL placeholder | Inferred when name matches `{placeholder}`. |
| `@Header({name, description})` | HTTP header | Must be explicit. |

### Response / metadata annotations

| Annotation | Usage |
| ---------- | ----- |
| `@ApiResponse(statusCode, description, contentType, bodyType)` | Document an additional response status. Stack multiple on one method. |
| `@Returns(statusCode, description, contentType, bodyType)` | Override the inferred success response, useful when the method returns `Response` directly. |
| `@Tag(name, description)` | Add extra OpenAPI tags to a single operation. |
| `@QueryDoc(name, type, required, description)` | Document a query parameter for raw-`Request` handlers. |
| `@BodyDoc(type, required, description, contentType)` | Document the request body for raw-`Request` handlers. |

Example combining several annotations:

```dart
@Get('/{id}', summary: 'Get product')
@Returns(bodyType: ProductResponse)
@ApiResponse(404, description: 'Product not found')
@QueryDoc('currency', type: String, description: 'ISO 4217 currency code')
Future<Response> getProduct(String id, Request request) async { ... }
```

## Parameter inference rules

The generator picks a source for each parameter in this order:

1. An explicit annotation: `@Path`, `@Query`, `@Header`, `@Body`.
2. A parameter named like a `{placeholder}` in the route path →
   **path** parameter.
3. A primitive (`int`, `String`, `double`, `bool`, `DateTime`, `num`) →
   **query** parameter.
4. A `shelf.Request` parameter → passed through untouched.
5. Anything else → **request body** (at most one per method). Decoded as
   JSON; calls `fromJson(Map<String, dynamic>)` if the type has one.

Nullable types (`int?`, `String?`) become `required: false` automatically.

---

## Response handling

| Return type | Behavior |
| ----------- | -------- |
| `Response` / `Future<Response>` | Passed through untouched. |
| `void` / `Future<void>` | Empty body with declared status code (`204` for `@Delete`). |
| Any other type | JSON-encoded via `toJson()` (recursive for `List<T>` / `Map<String, V>`). |

## JSON Schema inference

Each Dart class referenced as a body, return type, or parameter is
walked through its default constructor and emitted under
`#/components/schemas/{ClassName}`.

| Dart | OpenAPI schema |
| ---- | -------------- |
| `String` | `{type: string}` |
| `int` | `{type: integer, format: int64}` |
| `double` | `{type: number, format: double}` |
| `num` | `{type: number}` |
| `bool` | `{type: boolean}` |
| `DateTime` | `{type: string, format: date-time}` |
| `Uri` | `{type: string, format: uri}` |
| `List<T>` / `Iterable<T>` | `{type: array, items: <T>}` |
| `Set<T>` | `{type: array, items: <T>, uniqueItems: true}` |
| `enum Color { red, green }` | `{type: string, enum: [red, green]}` (an enum with its own `toJson()` is left open) |
| `Map<String, V>` | `{type: object, additionalProperties: <V>}` |
| Custom class | `{$ref: '#/components/schemas/MyClass'}` |
| Generic class `Page<User>` | `{$ref: '#/components/schemas/Page_User'}`, with `T` replaced by `User` |
| `T?` | Union with `'null'` (OpenAPI 3.1 style) |

Each instantiation of a generic class is its own component, named after
its type arguments: `Page<User>` is `Page_User`, `Page<List<Post?>>` is
`Page_List_PostNullable`.

## Authentication in the spec

Routes guarded with gisila's `@RequireAuth()`, `@Permissions`,
`@AnyPermission` or `@Roles` (on the method or the controller, unless the
method is `@Public()`) are documented as such:

- `security` lists every scheme in `OpenApiSpec.securitySchemes` as an
  alternative, with the route's roles and permissions as its values
  (OpenAPI 3.1 allows role names for non-OAuth schemes).
- a `401` response, and a `403` when permissions or roles apply, both with
  gisila's error body (`errorEnvelopeSchema`). A response the route
  declares itself with `@ApiResponse` takes precedence.
- `x-gisila-guards` with the raw `permissions`, `anyPermission` and
  `roles`, since "any of" has no standard OpenAPI form.

`securitySchemes` defaults to one HTTP bearer scheme, `bearerAuth`, which
is what gisila's authenticators read. It is emitted only when some route
is guarded. Pass your own, or `{}` to leave security out:

```dart
final spec = OpenApiSpec(
  info: ApiInfo(title: 'My API', version: '1.0.0'),
  securitySchemes: {
    'bearerAuth': SecurityScheme.bearer(),
    'session': SecurityScheme.apiKey(name: 'sid', location: 'cookie'),
  },
);
```

## OpenApiSpec reference

```dart
final spec = OpenApiSpec(
  openapi: '3.1.0',       // default
  info: ApiInfo(
    title: 'My API',
    version: '1.0.0',
    description: 'Optional markdown.',
    contact: Contact(email: 'api@example.com'),
    license: License(name: 'MIT', identifier: 'MIT'),
  ),
  servers: [
    ApiServer(url: 'https://api.example.com', description: 'Production'),
  ],
);

// Programmatic additions (after build_runner wires controllers):
spec.putTag('Admin', description: 'Admin-only operations');
spec.putSchema('ErrorEnvelope', {
  'type': 'object',
  'properties': {
    'error': {'\$ref': '#/components/schemas/ApiError'},
  },
});
```

Serialise at any time:

```dart
final json = spec.toJson();       // pretty-printed
final map  = spec.toMap();        // plain Map<String, Object?>
```

## Bundled docs handler

`docsHandler(spec)` mounts:

| Path | Content |
| ---- | ------- |
| `GET /openapi.json` | The rendered OpenAPI document. |
| `GET /docs` | Swagger UI (loaded from `unpkg.com`). |
| `GET /redoc` | ReDoc (loaded from `cdn.redoc.ly`). |

For offline bundles, use `spec.toJson()` and serve the file yourself.

---

## Error handling

`coerce` and `readJsonBody` throw `BadRequestException` when input is
malformed. The generated wrapper catches it and returns `400` with a JSON
envelope. `TypeError` and `FormatException` (typically from a hand-written
`fromJson`) are also turned into `400` responses, so a bad payload never
escapes as a `500`.

## Version compatibility

The generator is pinned to the legacy `analyzer` element API
(`ClassElement` / `ParameterElement` / `.parameters`) preserved in
`analyzer 7.x`. An `analyzer 8+` build will follow once `source_gen`
upstream stabilises on the new `Element2` API.
